📚 Guia Completo Next.js

🚀 Inicialização do Next.js

Métodos de Criação

1. create-next-app (Padrão)

O que é: Comando oficial para criar projeto Next.js.
Para que serve: Criar novo projeto Next.js com configurações padrão.
Importância: Método mais simples e recomendado.
npx create-next-app@latest meu-projeto
Quando usar: Para começar um novo projeto Next.js.
npx executa o pacote sem instalar globalmente.

2. Comando Interativo

O que é: Comando com perguntas interativas.
Para que serve: Personalizar configurações do projeto.
Importância: Controle total sobre configurações.
npx create-next-app@latest # Perguntas: # What is your project named? meu-projeto # Would you like to use TypeScript? No # Would you like to use ESLint? Yes # Would you like to use Tailwind CSS? No # Would you like to use `src/` directory? Yes # Would you like to use App Router? Yes # Would you like to customize the default import alias? No
Quando usar: Para personalizar configurações do projeto.
App Router é o padrão atual do Next.js 13+.

3. Comando com Flags

O que é: Comando com todas as flags pré-definidas.
Para que serve: Criar projeto sem perguntas interativas.
Importância: Mais rápido para projetos padrão.
npx create-next-app@latest meu-projeto --typescript --eslint --tailwind --src-dir --app --no-import-alias
Quando usar: Para criar projeto com configurações específicas.
Use --help para ver todas as flags disponíveis.
Comandos de Desenvolvimento

4. npm run dev

O que é: Inicia servidor de desenvolvimento.
Para que serve: Rodar aplicação em modo desenvolvimento.
Importância: Hot reload e debug.
npm run dev
Quando usar: Durante o desenvolvimento.
Servidor roda em http://localhost:3000 por padrão.

5. npm run build

O que é: Compila aplicação para produção.
Para que serve: Criar build otimizado para deploy.
Importância: Otimização e performance.
npm run build
Quando usar: Antes de fazer deploy.
Cria pasta .next com arquivos compilados.

6. npm start

O que é: Inicia servidor de produção.
Para que serve: Rodar aplicação em modo produção.
Importância: Simula ambiente de produção.
npm start
Quando usar: Após npm run build.
Requer build prévio.

7. npm run lint

O que é: Executa ESLint para verificar código.
Para que serve: Encontrar erros e problemas de código.
Importância: Qualidade do código.
npm run lint
Quando usar: Para verificar qualidade do código.
ESLint ajuda a manter código consistente.
Pré-requisitos

8. Node.js

O que é: Runtime JavaScript para servidor.
Para que serve: Executar JavaScript fora do navegador.
Importância: Next.js requer Node.js.
node --version # Verificar versão # Recomendado: Node.js 18.17 ou superior
Quando usar: Pré-requisito para Next.js.
Sempre use versão LTS (Long Term Support).

9. npm ou yarn ou pnpm

O que é: Gerenciador de pacotes.
Para que serve: Instalar dependências do projeto.
Importância: Gerenciamento de dependências.
npm --version # Verificar versão npm yarn --version # Verificar versão yarn pnpm --version # Verificar versão pnpm
Quando usar: Pré-requisito para Next.js.
npm vem instalado com Node.js.

📁 Estrutura do Projeto Next.js

Estrutura Básica

1. Estrutura Completa

O que é: Organização padrão de pastas Next.js.
Para que serve: Organização do código.
Importância: Estrutura recomendada pelo Next.js.
meu-projeto/ ├── src/ │ ├── app/ # App Router │ │ ├── page.tsx # Página principal │ │ ├── layout.tsx # Layout raiz │ │ └── globals.css # Estilos globais │ ├── components/ # Componentes reutilizáveis │ └── lib/ # Funções utilitárias ├── public/ # Arquivos estáticos ├── next.config.js # Configurações Next.js ├── package.json # Dependências └── tsconfig.json # Configurações TypeScript
Quando usar: Estrutura padrão com App Router.
app/ é o coração do App Router.

2. Pasta src/

O que é: Pasta principal do código fonte.
Para que serve: Organizar todo o código da aplicação.
Importância: Separação de código e configurações.
src/ ├── app/ ├── components/ └── lib/
Quando usar: Todo o código da aplicação vai aqui.
Opcional, mas recomendado pelo Next.js.

3. Pasta app/

O que é: Pasta do App Router.
Para que serve: Definir rotas e páginas.
Importância: Sistema de rotas do Next.js 13+.
app/ ├── page.tsx # Página principal (/) ├── layout.tsx # Layout raiz ├── globals.css # Estilos globais ├── about/ # Rota /about │ └── page.tsx └── users/ # Rota /users └── page.tsx
Quando usar: Para definir rotas da aplicação.
Cada pasta vira uma rota automaticamente.

4. Pasta public/

O que é: Pasta de arquivos estáticos.
Para que serve: Armazenar imagens, fontes, etc.
Importância: Arquivos servidos diretamente.
public/ ├── images/ │ └── logo.png ├── favicon.ico └── robots.txt
Quando usar: Para arquivos estáticos acessíveis publicamente.
Arquivos em public/ são acessíveis via URL.

5. next.config.js

O que é: Arquivo de configuração do Next.js.
Para que serve: Configurar comportamento do Next.js.
Importância: Personalização do framework.
/** @type {import('next').NextConfig} */ const nextConfig = { reactStrictMode: true, images: { domains: ['example.com'], }, } module.exports = nextConfig
Quando usar: Para configurar Next.js.
Criado automaticamente pelo create-next-app.

📄 Páginas no Next.js

App Router

1. page.tsx

O que é: Arquivo que define uma página.
Para que serve: Criar uma rota/página na aplicação.
Importância: Base do sistema de rotas.
// app/page.tsx export default function Home() { return ( <main> <h1>Página Principal</h1> </main> ); }
Quando usar: Para criar uma página.
page.tsx é obrigatório para cada rota.

2. layout.tsx

O que é: Arquivo que define layout compartilhado.
Para que serve: Compartilhar UI entre páginas.
Importância: Evita repetição de código.
// app/layout.tsx export default function RootLayout({ children, }: { children: React.ReactNode }) { return ( <html lang="pt-BR"> <body> <nav>Menu</nav> {children} <footer>Rodapé</footer> </body> </html> ); }
Quando usar: Para compartilhar layout entre páginas.
layout.tsx é opcional, mas recomendado.

3. globals.css

O que é: Arquivo de estilos globais.
Para que serve: Aplicar estilos a toda aplicação.
Importância: Estilos base da aplicação.
// app/globals.css @tailwind base; @tailwind components; @tailwind utilities; body { background-color: #f5f5f5; }
Quando usar: Para estilos globais.
Importado no layout.tsx.
Rotas Dinâmicas

4. Rotas Dinâmicas

O que é: Rotas com parâmetros dinâmicos.
Para que serve: Criar páginas com IDs variáveis.
Importância: Essencial para páginas de detalhes.
// app/users/[id]/page.tsx export default function UserPage({ params, }: { params: { id: string } }) { return <div>Usuário {params.id}</div> } // Rota: /users/1, /users/2, etc.
Quando usar: Para páginas com parâmetros dinâmicos.
[id] indica parâmetro dinâmico.

🧩 Componentes no Next.js

Componentes de Servidor

1. Server Components

O que é: Componentes que rodam no servidor.
Para que serve: Renderização no servidor (SSR).
Importância: Padrão no Next.js 13+.
// Padrão: Server Component export default function ServerComponent() { return <div>Renderizado no servidor</div> }
Quando usar: Para componentes que não precisam de interatividade.
Melhor performance e SEO.

2. Client Components

O que é: Componentes que rodam no cliente.
Para que serve: Interatividade (useState, useEffect).
Importância: Necessário para interatividade.
'use client'; import { useState } from 'react'; export default function ClientComponent() { const [count, setCount] = useState(0); return ( <button onClick={() => setCount(count + 1)}> {count} </button> ); }
Quando usar: Para componentes com interatividade.
'use client' no topo do arquivo.
Organização

3. Pasta components/

O que é: Pasta para componentes reutilizáveis.
Para que serve: Organizar componentes da aplicação.
Importância: Manutenibilidade e reutilização.
src/components/ ├── Button.tsx ├── Card.tsx ├── Header.tsx └── Footer.tsx
Quando usar: Para componentes reutilizáveis.
Componentes podem ser Server ou Client.

🛣️ Sistema de Rotas

Rotas Estáticas

1. Rotas Estáticas

O que é: Rotas fixas definidas pela estrutura de pastas.
Para que serve: Criar páginas estáticas.
Importância: Sistema de rotas baseado em arquivos.
app/ ├── page.tsx # / ├── about/ │ └── page.tsx # /about ├── contact/ │ └── page.tsx # /contact └── users/ └── page.tsx # /users
Quando usar: Para páginas estáticas.
Cada pasta vira uma rota automaticamente.
Rotas Dinâmicas

2. Rotas Dinâmicas

O que é: Rotas com parâmetros variáveis.
Para que serve: Criar páginas com IDs dinâmicos.
Importância: Essencial para páginas de detalhes.
app/ ├── users/ │ ├── [id]/ │ │ └── page.tsx # /users/1, /users/2 │ └── page.tsx # /users └── posts/ ├── [category]/ │ └── [id]/ │ └── page.tsx # /posts/tech/1 └── page.tsx # /posts
Quando usar: Para páginas com parâmetros dinâmicos.
[nome] indica parâmetro dinâmico.
Navegação

3. Link Component

O que é: Componente para navegação entre páginas.
Para que serve: Navegação client-side sem reload.
Importância: Performance e UX melhor.
import Link from 'next/link'; export default function Navigation() { return ( <nav> <Link href="/">Home</Link> <Link href="/about">Sobre</Link> <Link href="/users/1">Usuário 1</Link> </nav> ); }
Quando usar: Para navegação entre páginas.
Use Link em vez de <a> para navegação interna.

4. useRouter Hook

O que é: Hook para navegação programática.
Para que serve: Navegar programaticamente.
Importância: Navegação condicional.
'use client'; import { useRouter } from 'next/navigation'; export default function Button() { const router = useRouter(); return ( <button onClick={() => router.push('/about')}> Ir para Sobre </button> ); }
Quando usar: Para navegação programática.
Requer 'use client'.
