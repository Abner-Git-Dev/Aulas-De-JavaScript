📚 Git e GitHub - Guia Completo

Guia completo com todos os comandos e conceitos de Git e GitHub explicados detalhadamente.

1. O que é Git?

O que faz: Sistema de controle de versão distribuído.
Quando usar: Para rastrear mudanças em código e colaborar em equipe.
Importante: Git é local, roda no seu computador.
Git rastreia todas as mudanças no seu código
Permite voltar a versões anteriores
Facilita colaboração em equipe

2. O que é GitHub?

O que faz: Plataforma de hospedagem de repositórios Git.
Quando usar: Para armazenar e compartilhar código online.
Importante: GitHub é online, na nuvem.
GitHub armazena seus repositórios Git
Permite colaboração remota
Oferece ferramentas como issues, pull requests

3. git config

O que faz: Configura suas informações no Git.
Quando usar: Primeira vez que usa Git no computador.
Importante: Precisa configurar nome e email.
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
Resultado: Git configurado com seu nome e email

4. git init

O que faz: Inicia um repositório Git no diretório atual.
Quando usar: Quando começa um novo projeto.
Importante: Cria pasta .git oculta.
git init
Resultado: Repositório Git inicializado

5. git clone

O que faz: Copia um repositório existente para seu computador.
Quando usar: Para baixar um projeto do GitHub.
Importante: Cria cópia completa do repositório.
git clone https://github.com/usuario/repositorio.git
Resultado: Repositório copiado para seu computador

6. git status

O que faz: Mostra o estado do repositório.
Quando usar: Para verificar mudanças não commitadas.
Importante: Mostra arquivos modificados, adicionados, etc.
git status
Resultado: Estado atual do repositório

7. git add

O que faz: Adiciona arquivos à área de staging.
Quando usar: Antes de fazer commit.
Importante: Prepara arquivos para serem commitados.
git add arquivo.js // Arquivo específico
git add . // Todos os arquivos
git add *.js // Todos os arquivos .js
Resultado: Arquivos na área de staging

8. git commit

O que faz: Salva mudanças no repositório local.
Quando usar: Após adicionar arquivos com git add.
Importante: Sempre inclua mensagem descritiva.
git commit -m "Mensagem descritiva"
git commit -am "Mensagem" // Add + commit juntos
Resultado: Mudanças salvas no repositório local

9. git push

O que faz: Envia commits locais para o GitHub.
Quando usar: Para atualizar repositório remoto.
Importante: Precisa ter commits locais para enviar.
git push // Push padrão
git push origin main // Push para branch específico
git push -u origin main // Primeiro push com upstream
Resultado: Commits enviados para GitHub

10. git pull

O que faz: Baixa mudanças do GitHub para seu computador.
Quando usar: Para atualizar seu repositório local.
Importante: Combina git fetch + git merge.
git pull // Pull padrão
git pull origin main // Pull de branch específico
Resultado: Mudanças baixadas do GitHub

11. git log

O que faz: Mostra histórico de commits.
Quando usar: Para ver mudanças anteriores.
Importante: Mostra hash, autor, data, mensagem.
git log // Histórico completo
git log --oneline // Uma linha por commit
git log --graph // Com gráfico visual
Resultado: Histórico de commits

12. git branch

O que faz: Gerencia branches (ramificações).
Quando usar: Para trabalhar em features separadas.
Importante: Branches permitem trabalho paralelo.
git branch // Lista branches
git branch nome-branch // Cria novo branch
git branch -d nome-branch // Deleta branch
Resultado: Branches gerenciados

13. git checkout

O que faz: Muda entre branches ou restaura arquivos.
Quando usar: Para trocar de branch ou voltar versão.
Importante: Mudanças não salvas podem ser perdidas.
git checkout nome-branch // Muda para branch
git checkout -- arquivo.js // Restaura arquivo
Resultado: Branch alterado ou arquivo restaurado

14. git merge

O que faz: Combina branches.
Quando usar: Para integrar mudanças de outro branch.
Importante: Pode causar conflitos.
git merge nome-branch // Merge branch atual
Resultado: Branches combinados

15. git diff

O que faz: Mostra diferenças entre arquivos.
Quando usar: Para ver mudanças não commitadas.
Importante: Mostra linhas adicionadas/removidas.
git diff // Mudanças não staging
git diff --staged // Mudanças staging
git diff branch1 branch2 // Diferença entre branches
Resultado: Diferenças entre arquivos

16. git reset

O que faz: Desfaze commits ou staging.
Quando usar: Para corrigir erros.
Importante: Cuidado, pode perder mudanças.
git reset // Remove do staging
git reset --hard HEAD~1 // Desfaz último commit
git reset --soft HEAD~1 // Desfaz commit, mantém staging
Resultado: Commits ou staging desfeitos

17. git rm

O que faz: Remove arquivos do Git.
Quando usar: Para deletar arquivos do repositório.
Importante: Remove do Git e do disco.
git rm arquivo.js // Remove arquivo
git rm --cached arquivo.js // Remove apenas do Git
Resultado: Arquivo removido do Git

18. .gitignore

O que faz: Arquivo que especifica o que ignorar.
Quando usar: Para não commitar arquivos desnecessários.
Importante: Padrões comuns: node_modules, .env, etc.
node_modules/
.env
.DS_Store
*.log
Resultado: Arquivos ignorados pelo Git

19. Criar Repositório no GitHub

O que faz: Cria novo repositório no GitHub.
Quando usar: Para começar um novo projeto online.
Importante: Pode ser público ou privado.
1. Acesse github.com
2. Clique em "+" → "New repository"
3. Dê nome e descrição
4. Escolha público/privado
5. Clique em "Create repository"
Resultado: Repositório criado no GitHub

20. Conectar Local com Remoto

O que faz: Conecta repositório local ao GitHub.
Quando usar: Após criar repositório no GitHub.
Importante: Precisa da URL do repositório.
git remote add origin https://github.com/usuario/repositorio.git
git branch -M main
git push -u origin main
Resultado: Repositório conectado ao GitHub

21. git push --force

O que faz: Força push sobrescrevendo remoto.
Quando usar: Apenas em emergências (cuidado!).
Importante: Pode perder mudanças de outros.
git push --force // Força push
git push --force-with-lease // Mais seguro
Resultado: Push forçado (use com cuidado!)

22. git stash

O que faz: Salva mudanças temporariamente.
Quando usar: Para trabalhar em outra tarefa.
Importante: Não commita, apenas guarda.
git stash // Salva mudanças
git stash list // Lista stashes
git stash pop // Restaura stash
Resultado: Mudanças salvas temporariamente

23. git fetch

O que faz: Baixa mudanças sem mesclar.
Quando usar: Para ver mudanças antes de merge.
Importante: Diferente de pull (não merge automaticamente).
git fetch // Baixa mudanças
git fetch origin // Baixa de origin
Resultado: Mudanças baixadas sem merge
