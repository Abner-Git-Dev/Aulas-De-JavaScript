📚 Guia Completo de APIs

🎯 Conceitos Fundamentais de API

O que é API

1. API (Application Programming Interface)

O que é: Interface de Programação de Aplicativos.
Para que serve: Permitir comunicação entre diferentes sistemas.
Importância: Base da comunicação entre front-end e back-end.
// Exemplo: Front-end chamando API fetch('https://api.exemplo.com/usuarios') .then(response => response.json()) .then(data => console.log(data));
Quando usar: Sempre que precisar comunicar sistemas diferentes.
API é como um "garçom" que leva pedidos entre cliente e cozinha.

2. Tipos de API

O que é: Diferentes formas de comunicação via API.
Para que serve: Escolher o melhor tipo para cada caso.
Importância: Cada tipo tem suas vantagens.
// REST API (mais comum) GET https://api.exemplo.com/usuarios // GraphQL (alternativa) query { usuarios { nome email } } // SOAP (mais antigo, corporativo) <soap:Envelope> <soap:Body> <m:GetUsuario> <m:Id>1</m:Id> </m:GetUsuario> </soap:Body> </soap:Envelope>
Quando usar: REST é o padrão mais usado.
REST é o padrão da indústria para APIs web.

3. Cliente e Servidor

O que é: Dois lados da comunicação API.
Para que serve: Entender quem faz o pedido e quem responde.
Importância: Base da arquitetura cliente-servidor.
// Cliente (Front-end) fetch('https://api.exemplo.com/usuarios') .then(res => res.json()) .then(data => console.log(data)); // Servidor (Back-end) app.get('/usuarios', (req, res) => { res.json({ usuarios: [...] }); });
Quando usar: Sempre que criar ou consumir APIs.
Cliente faz requisição, servidor responde.

4. Request (Requisição) e Response (Resposta)

O que é: Ciclo de comunicação API.
Para que serve: Cliente envia request, servidor envia response.
Importância: Entender o fluxo de dados.
// Request (Cliente → Servidor) { method: 'GET', url: 'https://api.exemplo.com/usuarios', headers: { 'Content-Type': 'application/json' } } // Response (Servidor → Cliente) { status: 200, data: { usuarios: [ { id: 1, nome: 'Abner' }, { id: 2, nome: 'Samira' } ] } }
Quando usar: Sempre que trabalhar com APIs.
Request = pedido, Response = resposta.

5. Endpoint

O que é: URL específica de uma API.
Para que serve: Definir onde cada recurso está acessível.
Importância: Cada endpoint faz uma coisa específica.
// Endpoints de uma API de usuários GET /api/usuarios # Listar todos GET /api/usuarios/:id # Buscar um usuário POST /api/usuarios # Criar usuário PUT /api/usuarios/:id # Atualizar usuário DELETE /api/usuarios/:id # Deletar usuário
Quando usar: Para definir rotas da API.
:id indica parâmetro dinâmico.

🌐 Protocolo HTTP

Métodos HTTP

1. GET

O que é: Método para buscar dados.
Para que serve: Recuperar informações do servidor.
Importância: Método mais usado, seguro e cacheável.
// Buscar todos os usuários GET /api/usuarios // Buscar usuário específico GET /api/usuarios/1 // Com parâmetros de query GET /api/usuarios?idade=23&cidade=sp
Quando usar: Para ler/buscar dados.
GET não deve alterar dados no servidor.

2. POST

O que é: Método para criar dados.
Para que serve: Enviar dados para criar novo recurso.
Importância: Usado para cadastro e criação.
// Criar novo usuário POST /api/usuarios Content-Type: application/json { "nome": "Abner", "idade": 23, "email": "abn@email.com" }
Quando usar: Para criar novos recursos.
Dados vão no body da requisição.

3. PUT

O que é: Método para atualizar dados completos.
Para que serve: Substituir todo o recurso.
Importância: Atualização completa de um recurso.
// Atualizar usuário completo PUT /api/usuarios/1 Content-Type: application/json { "nome": "Abner Atualizado", "idade": 24, "email": "abn@email.com" }
Quando usar: Para atualizar recurso inteiro.
PUT substitui todos os dados do recurso.

4. PATCH

O que é: Método para atualização parcial.
Para que serve: Atualizar apenas alguns campos.
Importância: Mais eficiente para atualizações parciais.
// Atualizar apenas o email PATCH /api/usuarios/1 Content-Type: application/json { "email": "novo@email.com" }
Quando usar: Para atualizar campos específicos.
PATCH atualiza apenas o que foi enviado.

5. DELETE

O que é: Método para deletar dados.
Para que serve: Remover um recurso do servidor.
Importância: Usado para exclusão de dados.
// Deletar usuário DELETE /api/usuarios/1
Quando usar: Para remover recursos.
DELETE geralmente não tem body.
Status Codes

6. Códigos de Status HTTP

O que é: Códigos que indicam resultado da requisição.
Para que serve: Informar se requisição foi bem-sucedida.
Importância: Essencial para tratamento de erros.
// Sucesso (2xx) 200 OK # Requisição bem-sucedida 201 Created # Recurso criado com sucesso 204 No Content # Requisição bem-sucedida, sem conteúdo // Redirecionamento (3xx) 301 Moved Permanently # URL mudou permanentemente 302 Found # Redirecionamento temporário // Erro do Cliente (4xx) 400 Bad Request # Requisição inválida 401 Unauthorized # Não autenticado 403 Forbidden # Sem permissão 404 Not Found # Recurso não encontrado // Erro do Servidor (5xx) 500 Internal Server Error # Erro no servidor 503 Service Unavailable # Servidor indisponível
Quando usar: Sempre que fazer requisições HTTP.
2xx = sucesso, 4xx = erro cliente, 5xx = erro servidor.
Headers

7. Headers HTTP

O what é: Metadados da requisição/resposta.
Para que serve: Enviar informações adicionais.
Importância: Autenticação, tipo de conteúdo, etc.
// Headers comuns Content-Type: application/json # Tipo do conteúdo Authorization: Bearer token123 # Token de autenticação Accept: application/json # Tipo aceito na resposta User-Agent: Mozilla/5.0 # Informações do cliente Cache-Control: no-cache # Controle de cache
Quando usar: Para enviar metadados importantes.
Content-Type é o header mais importante.

🔄 REST API

Princípios REST

1. O que é REST

O que é: Representational State Transfer.
Para que serve: Arquitetura para APIs web.
Importância: Padrão mais usado para APIs.
// Exemplo de API RESTful GET /api/usuarios # Listar usuários GET /api/usuarios/1 # Buscar usuário 1 POST /api/usuarios # Criar usuário PUT /api/usuarios/1 # Atualizar usuário 1 DELETE /api/usuarios/1 # Deletar usuário 1
Quando usar: Para criar APIs web padrão.
REST usa métodos HTTP e recursos (URLs).

2. Recursos

O que é: Entidades da API (usuários, produtos).
Para que serve: Organizar a API em entidades.
Importância: Base da arquitetura REST.
// Recursos em uma API /api/usuarios # Recurso: usuários /api/produtos # Recurso: produtos /api/pedidos # Recurso: pedidos /api/categorias # Recurso: categorias // Sub-recursos /api/usuarios/1/pedidos # Pedidos do usuário 1 /api/produtos/1/avaliacoes # Avaliações do produto 1
Quando usar: Para organizar endpoints da API.
Recursos devem ser substantivos (plural).

3. Verbos HTTP

O que é: Ações sobre recursos.
Para que serve: Definir operação CRUD.
Importância: Mapeamento correto de operações.
// CRUD com HTTP CREATE → POST /api/usuarios READ → GET /api/usuarios UPDATE → PUT /api/usuarios/1 DELETE → DELETE /api/usuarios/1
Quando usar: Para implementar operações CRUD.
Use verbos HTTP corretos para cada operação.

4. JSON (JavaScript Object Notation)

O que é: Formato de dados padrão para APIs.
Para que serve: Troca de dados entre sistemas.
Importância: Leve, legível e universal.
// Exemplo de JSON { "id": 1, "nome": "Abner", "idade": 23, "email": "abn@email.com", "endereco": { "rua": "Rua A", "cidade": "São Paulo" } } // Array de JSON [ { "id": 1, "nome": "Abner" }, { "id": 2, "nome": "Samira" } ]
Quando usar: Para enviar/receber dados em APIs.
JSON é o formato padrão de APIs REST.

5. Versionamento de API

O que é: Controle de versões da API.
Para que serve: Manter compatibilidade com clientes antigos.
Importância: Evita quebrar aplicações que usam a API.
// Versionamento na URL /api/v1/usuarios /api/v2/usuarios // Versionamento no header GET /api/usuarios API-Version: v1
Quando usar: Quando precisar mudar a API.
Versionamento na URL é mais comum.

⚡ Express.js

Instalação e Setup

1. Instalar Express

O que é: Framework web para Node.js.
Para que serve: Criar APIs rapidamente.
Importância: Framework mais popular para APIs em Node.js.
# Criar projeto npm init -y # Instalar Express npm install express # Instalar nodemon (para desenvolvimento) npm install --save-dev nodemon
Quando usar: Para criar API com Node.js.
nodemon reinicia servidor automaticamente.

2. Servidor Básico

O que é: Servidor Express simples.
Para que serve: Iniciar API básica.
Importância: Ponto de partida para qualquer API.
const express = require('express'); const app = express(); // Middleware para JSON app.use(express.json()); // Rota básica app.get('/', (req, res) => { res.json({ mensagem: 'API funcionando!' }); }); // Iniciar servidor app.listen(3000, () => { console.log('Servidor rodando na porta 3000'); });
Quando usar: Para criar servidor Express.
express.json() é essencial para receber JSON.
Rotas

3. Rotas GET

O que é: Rota para buscar dados.
Para que serve: Implementar operações de leitura.
Importância: Operação mais comum em APIs.
// Listar todos os usuários app.get('/usuarios', (req, res) => { const usuarios = [ { id: 1, nome: 'Abner' }, { id: 2, nome: 'Samira' } ]; res.json(usuarios); }); // Buscar usuário por ID app.get('/usuarios/:id', (req, res) => { const { id } = req.params; const usuario = { id: id, nome: 'Abner' }; res.json(usuario); });
Quando usar: Para implementar endpoints de leitura.
req.params contém parâmetros da URL.

4. Rotas POST

O que é: Rota para criar dados.
Para que serve: Implementar operações de criação.
Importância: Essencial para cadastros.
// Criar novo usuário app.post('/usuarios', (req, res) => { const { nome, idade, email } = req.body; const novoUsuario = { id: Date.now(), nome, idade, email }; res.status(201).json(novoUsuario); });
Quando usar: Para implementar endpoints de criação.
req.body contém dados enviados no corpo da requisição.

5. Rotas PUT/PATCH

O que é: Rota para atualizar dados.
Para que serve: Implementar operações de atualização.
Importância: Essencial para edição de dados.
// Atualizar usuário (PUT) app.put('/usuarios/:id', (req, res) => { const { id } = req.params; const { nome, idade, email } = req.body; const usuarioAtualizado = { id, nome, idade, email }; res.json(usuarioAtualizado); }); // Atualizar parcial (PATCH) app.patch('/usuarios/:id', (req, res) => { const { id } = req.params; const dadosAtualizacao = req.body; // Atualiza apenas campos enviados const usuarioAtualizado = { id, ...dadosAtualizacao }; res.json(usuarioAtualizado); });
Quando usar: Para implementar endpoints de atualização.
PUT atualiza tudo, PATCH atualiza parcialmente.

6. Rotas DELETE

O que é: Rota para deletar dados.
Para que serve: Implementar operações de exclusão.
Importância: Essencial para remoção de dados.
// Deletar usuário app.delete('/usuarios/:id', (req, res) => { const { id } = req.params; // Lógica para deletar usuário console.log(`Usuário ${id} deletado`); res.status(204).send(); });
Quando usar: Para implementar endpoints de exclusão.
204 No Content é o status correto para DELETE.
Middleware

7. Middleware

O que é: Funções que executam antes das rotas.
Para que serve: Processar requisições.
Importância: Autenticação, logging, validação.
// Middleware de logging app.use((req, res, next) => { console.log(`${req.method} ${req.url}`); next(); }); // Middleware de autenticação const autenticar = (req, res, next) => { const token = req.headers.authorization; if (!token) { return res.status(401).json({ erro: 'Não autorizado' }); } next(); }; // Usar middleware em rota app.get('/protegido', autenticar, (req, res) => { res.json({ mensagem: 'Acesso concedido' }); });
Quando usar: Para processar requisições.
next() é obrigatório para continuar para próxima função.

📝 CRUD Completo com Express

Projeto Completo

1. API CRUD Completa

O que é: API com todas as operações CRUD.
Para que serve: Exemplo completo de API REST.
Importância: Base para qualquer projeto real.
const express = require('express'); const app = express(); app.use(express.json()); // Dados em memória (simulando banco) let usuarios = [ { id: 1, nome: 'Abner', idade: 23, email: 'abn@email.com' }, { id: 2, nome: 'Samira', idade: 22, email: 'sami@email.com' } ]; // CREATE - Criar usuário app.post('/usuarios', (req, res) => { const { nome, idade, email } = req.body; if (!nome || !idade || !email) { return res.status(400).json({ erro: 'Campos obrigatórios' }); } const novoUsuario = { id: Date.now(), nome, idade, email }; usuarios.push(novoUsuario); res.status(201).json(novoUsuario); }); // READ - Listar todos app.get('/usuarios', (req, res) => { res.json(usuarios); }); // READ - Buscar por ID app.get('/usuarios/:id', (req, res) => { const { id } = req.params; const usuario = usuarios.find(u => u.id == id); if (!usuario) { return res.status(404).json({ erro: 'Usuário não encontrado' }); } res.json(usuario); }); // UPDATE - Atualizar usuário app.put('/usuarios/:id', (req, res) => { const { id } = req.params; const { nome, idade, email } = req.body; const index = usuarios.findIndex(u => u.id == id); if (index === -1) { return res.status(404).json({ erro: 'Usuário não encontrado' }); } usuarios[index] = { id: parseInt(id), nome, idade, email }; res.json(usuarios[index]); }); // DELETE - Deletar usuário app.delete('/usuarios/:id', (req, res) => { const { id } = req.params; const index = usuarios.findIndex(u => u.id == id); if (index === -1) { return res.status(404).json({ erro: 'Usuário não encontrado' }); } usuarios.splice(index, 1); res.status(204).send(); }); app.listen(3000, () => { console.log('API rodando na porta 3000'); });
Quando usar: Como base para projetos reais.
Em produção, substitua array por banco de dados.

2. Testando a API

O que é: Como testar os endpoints.
Para que serve: Verificar se API está funcionando.
Importância: Essencial durante desenvolvimento.
# Testar com curl curl http://localhost:3000/usuarios curl -X POST http://localhost:3000/usuarios \ -H "Content-Type: application/json" \ -d '{"nome":"João","idade":25,"email":"joao@email.com"}' curl -X PUT http://localhost:3000/usuarios/1 \ -H "Content-Type: application/json" \ -d '{"nome":"João Atualizado","idade":26,"email":"joao@email.com"}' curl -X DELETE http://localhost:3000/usuarios/1 # Ou usar ferramentas como Postman, Insomnia
Quando usar: Para testar endpoints durante desenvolvimento.
Postman é a ferramenta mais popular para testar APIs.

3. Boas Práticas

O que é: Práticas recomendadas para APIs.
Para que serve: Criar APIs profissionais.
Importância: Qualidade e manutenibilidade.
// ✅ Boas Práticas // 1. Validação de dados if (!nome || !email) { return res.status(400).json({ erro: 'Campos obrigatórios' }); } // 2. Tratamento de erros try { // código } catch (error) { res.status(500).json({ erro: 'Erro interno' }); } // 3. Quando usar: Sempre ao criar APIs.
Validação e tratamento de erros são essenciais.
