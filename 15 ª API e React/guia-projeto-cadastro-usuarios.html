Estrutura

React

2. React Hooks usados

Três hooks nativos do React foram usados no componente Home.

HookPara que serveOnde foi usado
useState Guarda a lista de usuários em estado, disparando re-render quando muda. const [users, setUsers] = useState([])
useEffect Executa código quando o componente é montado — nesse caso, buscar os usuários assim que a tela carrega. useEffect(() => { getUsers() }, [])
useRef Referência direta a elementos DOM (inputs), sem precisar de estado controlado, para ler o valor digitado na hora de cadastrar. inputName, inputAge, inputEmail
Front-end

3. Componente Home.jsx

Componente principal: busca usuários da API, exibe em cards, permite cadastrar (POST) e deletar (DELETE).

src/pages/Home/index.jsx
import { useEffect , useState , useRef} from 'react'
import './style.css'
import Trash from '../../assets/trash.svg'
import api from '../../services/api'

//useEffect e useState = React Hooks

function Home() {

  const [users, setUsers] = useState([])

  const inputName = useRef()
  const inputAge = useRef()
  const inputEmail = useRef()

  async function getUsers() {
    const usersFromApi = await api.get('/usuarios')
    setUsers(usersFromApi.data)
  }

  async function createUsers(){
    await api.post('/usuarios', {
      name: inputName.current.value,
      age: inputAge.current.value,
      email: inputEmail.current.value
    })
    getUsers()
  }

  async function deleteUsers(id) {
    await api.delete(`/usuarios/${id}`)
    getUsers()
  }

  useEffect(() => {
    getUsers()
  }, [])

  return (
    <div className='container'>
      <form>
        <h1>Cadastro De Usuários</h1>
        <input placeholder="Nome" name="nome" type="text" ref={inputName}/>
        <input placeholder="Idade" name="idade" type="number" ref={inputAge}/>
        <input placeholder="Email" name="email" type="email" ref={inputEmail}/>
        <button type="button" className='cadastrar-button' onClick={createUsers}>Cadastrar</button>
      </form>

      {users.map(user => (
        <div key={user.id} className='card'>
          <div>
            <p>Nome: <span>{user.name}</span></p>
            <p>Idade: <span>{user.age}</span></p>
            <p>Email: <span>{user.email}</span></p>
            <button onClick={() => deleteUsers(user.id)}>
              <img src={Trash} />
            </button>
          </div>
        </div>
      ))}
    </div>
  );
}

export default Home

Back-end

5. Backend (Express + Prisma)

API REST com Express, usando Prisma como ORM para acessar o banco. Quatro rotas para o CRUD de usuários.

MétodoRotaAção
POST/usuariosCria um novo usuário
GET/usuariosLista usuários (com filtro opcional por query)
PUT/usuarios/:idAtualiza um usuário existente
DELETE/usuarios/:idRemove um usuário
server.js
import express from "express"
import cors from "cors"
import pkg from '@prisma/client'
const { PrismaClient } = pkg

const prisma = new PrismaClient()
const app = express()
app.use(express.json())
app.use(cors())

app.post('/usuarios', async (req, res) => {
  await prisma.user.create({
    data: {
      email: req.body.email,
      name: req.body.name,
      age: req.body.age
    }
  })
  res.status(201).json(req.body)
})

app.get('/usuarios', async (req, res) => {
  let users = []
  if (req.query) {
    users = await prisma.user.findMany({
      where: {
        name: req.query.name,
        email: req.query.email,
        age: req.query.age
      }
    })
  } else {
    users = await prisma.user.findMany()
  }
  res.status(200).json(users)
})

app.put('/usuarios/:id', async (req, res) => {
  const updated = await prisma.user.update({
    where: { id: req.params.id },
    data: {
      email: req.body.email,
      name: req.body.name,
      age: req.body.age
    }
  })
  res.status(200).json(updated)
})

app.delete('/usuarios/:id', async (req, res) => {
  await prisma.user.delete({
    where: { id: req.params.id }
  })
  res.status(200).json({ message: 'Usuário deletado com Sucesso!' })
})

app.listen(3000)
Correções aplicadas nesta versão do guia: no GET, o código original tinha prisma.user.findMany sem os parênteses () no else — isso retorna a função, não os dados. No PUT, havia um users.push(req.body) que não existia mais nesse escopo; foi trocado por retornar o registro atualizado direto do Prisma.

Debug

8. Erros encontrados e correções

Problemas reais que apareceram durante o desenvolvimento e como foram resolvidos.

1. Expected "}" but found EOF

A função getUsers não tinha o } de fechamento, fazendo com que createUsers, deleteUsers e o resto do arquivo ficassem aninhados dentro dela por engano. Corrigido fechando getUsers antes de declarar as próximas funções.

2. Atributos JSX colados

type="email"ref={inputEmail} — faltava espaço entre os atributos type e ref, o que quebra o parser JSX.

3. findMany sem parênteses

No back-end, prisma.user.findMany (sem ()) retorna a referência da função, não o resultado da busca — precisa ser prisma.user.findMany().

4. Variável users inexistente no PUT

Sobrou um users.push(req.body) de uma versão anterior do código (com array em memória) que não fazia mais sentido depois da migração para Prisma.

Atenção

9. Ponto de atenção: segurança

Credenciais de banco não devem ficar no código. Usuário e senha do banco apareceram comentados no final do server.js. Isso é um risco real caso o repositório seja publicado (ex: GitHub). O ideal é mover essas informações para um arquivo .env (usando o pacote dotenv) e nunca commitar esse arquivo — além de trocar a senha caso ela já tenha sido exposta em algum lugar.

10. Tecnologias usadas — explicação detalhada

Aqui vai o que cada peça do projeto realmente é, para que serve e por que foi escolhida.

React

Biblioteca JavaScript para construir interfaces de usuário baseadas em componentes — pedaços reutilizáveis de UI que têm seu próprio estado e lógica. Em vez de manipular o HTML diretamente (como no JS puro), você descreve "como a tela deveria ficar" para um dado estado, e o React se encarrega de atualizar o DOM real quando esse estado muda. No projeto, o Home é o componente principal que representa toda a tela de cadastro.

Vite

Ferramenta de build usada para criar e rodar o projeto React. Ele é responsável por servir os arquivos em desenvolvimento com atualização instantânea (Hot Module Replacement) e por empacotar tudo para produção. É o motivo de existir o index.html com <script type="module" src="/src/main.jsx"> — o Vite trabalha com módulos ES nativos.

useState

Hook do React que cria uma variável de estado. Diferente de uma variável comum, quando você atualiza um estado (com a função retornada, ex: setUsers), o React re-renderiza o componente automaticamente para refletir o novo valor na tela. No projeto, users guarda a lista vinda da API, e toda vez que setUsers é chamado, os cards na tela são redesenhados.

useEffect

Hook que executa um "efeito colateral" — código que interage com algo fora do React, como uma chamada de API, um timer, ou manipulação direta do DOM. O array de dependências no final ([]) controla quando esse código roda: com array vazio, ele roda uma única vez, logo depois que o componente aparece na tela. É por isso que getUsers() dentro do useEffect busca os usuários assim que a página carrega.

useRef

Hook que cria uma referência que aponta diretamente para um elemento do DOM (ou guarda um valor que não precisa causar re-render ao mudar). No projeto, cada input (nome, idade, email) tem um ref associado, e o valor digitado é lido via inputName.current.value na hora de cadastrar — uma alternativa mais simples a usar useState para cada campo do formulário (chamado de "input não controlado").

Axios

Biblioteca para fazer requisições HTTP (GET, POST, PUT, DELETE) a partir do JavaScript, tanto no navegador quanto no Node. É uma alternativa ao fetch nativo, com sintaxe mais simples e recursos como interceptadores e configuração de instância. No projeto, axios.create({ baseURL: ... }) cria uma instância pré-configurada apontando pro backend, evitando repetir a URL completa em cada chamada.

API REST

Um padrão de comunicação entre front-end e back-end baseado em métodos HTTP e URLs que representam "recursos". Aqui o recurso é /usuarios, e cada método HTTP tem um significado: GET busca, POST cria, PUT atualiza, DELETE remove. O front-end (React) nunca fala direto com o banco de dados — ele sempre passa por essa API.

Express

Framework para Node.js usado para criar servidores web e APIs de forma simples. Ele cuida de receber requisições HTTP, rotear para a função certa (app.get, app.post, etc.) e enviar a resposta. É a base do server.js — sem ele, você teria que lidar manualmente com o módulo http nativo do Node, que é bem mais verboso.

CORS (Cross-Origin Resource Sharing)

Por padrão, navegadores bloqueiam requisições feitas de um domínio/porta para outro diferente (por segurança). Como o front (ex: localhost:5173) e o back (localhost:3000) rodam em portas diferentes, é preciso liberar isso explicitamente. O middleware app.use(cors()) no Express adiciona os cabeçalhos necessários para o navegador permitir essa comunicação.

express.json()

Middleware do Express que interpreta o corpo (body) das requisições recebidas como JSON e transforma em um objeto JavaScript acessível via req.body. Sem ele, req.body chegaria vazio ou indefinido, mesmo que o front-end esteja enviando dados corretamente.

Prisma

ORM (Object-Relational Mapper) para Node.js — uma camada que traduz operações no banco de dados (criar, buscar, atualizar, deletar) em chamadas de métodos JavaScript, sem precisar escrever SQL manualmente. prisma.user.create(), findMany(), update() e delete() são exemplos disso. O Prisma também gera automaticamente os tipos e a estrutura com base num arquivo de schema (schema.prisma), o que ajuda a evitar erros de digitação em nomes de campos.

async / await

Sintaxe do JavaScript para lidar com código assíncrono (operações que demoram, como chamadas de rede ou de banco de dados) de forma que se lê como código síncrono, linha por linha. Uma função marcada com async pode usar await na frente de uma Promise para "pausar" a execução até o resultado voltar, sem travar o restante da aplicação. Praticamente todas as funções do projeto que falam com a API ou com o banco usam esse padrão.

Template literals (crase)

Strings delimitadas por crase (`) que permitem inserir variáveis diretamente no texto usando ${variavel}, sem precisar concatenar com +. Usado em `/usuarios/${id}` para montar a URL da requisição de exclusão com o id dinâmico do usuário.

Array.map()

Método nativo de arrays em JavaScript que cria um novo array transformando cada item do array original. No React, é o padrão usado para transformar uma lista de dados (os usuários) em uma lista de elementos JSX (os cards), um pra cada usuário — por isso users.map(user => (...)) dentro do return.

Thunder Client

Extensão do VS Code que funciona como um cliente HTTP (similar ao Postman), usada para testar rotas de API manualmente — montando o método, a URL e o corpo da requisição — sem precisar que o front-end esteja pronto. Foi usada aqui pra validar as quatro rotas (GET, POST, PUT, DELETE) antes de ligar tudo ao React.

CSS Nesting (aninhamento nativo com &)

Recurso relativamente novo do CSS que permite aninhar seletores dentro de outros, parecido com o que o Sass/SCSS já fazia — mas nativo do navegador. O & representa o seletor pai. No projeto, .card { & p { ... } } aplica o estilo a todo <p> dentro de .card, sem precisar escrever .card p separadamente.

Flexbox

Modelo de layout do CSS usado para alinhar e distribuir elementos em uma linha ou coluna de forma flexível. Usado no .container (organiza tudo em coluna, centralizado) e no .card (organiza texto e botão lado a lado, com espaço entre eles via justify-content: space-between).

Terminal

11. Comandos usados no terminal

Sequência de comandos para montar o projeto do zero — front-end (React + Vite) e back-end (Express + Prisma) — e colocar tudo rodando.

Criar o projeto React (front-end)

Cria a base do projeto usando o Vite com template React.

npm create vite@latest nome-do-projeto -- --template react
cd nome-do-projeto
npm install

Rodar o front-end (modo desenvolvimento)

Inicia o servidor local do Vite, com hot-reload — normalmente sobe em http://localhost:5173.

npm run dev

Instalar o axios no front-end

Biblioteca usada no services/api.js para fazer as requisições HTTP à API.

npm install axios

Criar o projeto do back-end

Inicializa um projeto Node.js do zero, gerando o package.json.

mkdir backend
cd backend
npm init -y

Habilitar ES Modules (import/export)

Para poder usar import/export (em vez de require) no server.js, é preciso adicionar essa linha no package.json do back-end:

{
  "type": "module"
}

Instalar Express e CORS

Framework do servidor e middleware para liberar requisições entre front e back em portas diferentes.

npm install express cors

Instalar e configurar o Prisma

Instala o Prisma como dependência de desenvolvimento, o client (usado no código) e inicializa a estrutura do ORM (gera a pasta prisma/ com o schema.prisma e o arquivo .env).

npm install prisma --save-dev
npm install @prisma/client
npx prisma init

Rodar a migração do banco

Depois de definir o model User no schema.prisma, esse comando cria as tabelas de fato no banco de dados com base nesse schema.

npx prisma migrate dev --name init

Abrir o Prisma Studio (opcional)

Interface visual no navegador para ver e editar os dados do banco diretamente, sem precisar de SQL.

npx prisma studio

Rodar o back-end

Executa o servidor Express. Com node puro, é preciso reiniciar manualmente a cada alteração; com nodemon, ele reinicia sozinho.

// rodar uma vez
node server.js

// ou, instalando o nodemon pra reiniciar sozinho a cada mudança
npm install --save-dev nodemon
npx nodemon server.js
Resumo do fluxo completo pra rodar o projeto: abrir dois terminais — um dentro da pasta do back-end rodando node server.js (ou npx nodemon server.js) na porta 3000, e outro dentro da pasta do front-end rodando npm run dev na porta 5173. Com os dois no ar, o React consegue falar com a API normalmente.

O que faz cada parte:

• <link rel="preconnect"> avisa o navegador com antecedência que ele vai baixar recursos do Google Fonts, acelerando o carregamento da fonte.
• O segundo <link> importa de fato a fonte Poppins em vários pesos (100 a 900), usada em todo o CSS do projeto.
• <meta charset="UTF-8"> garante que acentos e caracteres especiais (como "ç", "ã") sejam exibidos corretamente.
• <meta name="viewport"> faz o site se adaptar a telas de celular, em vez de renderizar como se fosse desktop.
• <div id="root"> é o elemento vazio onde o React vai "injetar" toda a aplicação — é o único elemento do HTML que existe antes do JavaScript rodar.
• <script type="module" src="/src/main.jsx"> carrega o arquivo que efetivamente inicia o React. O type="module" é necessário porque esse arquivo usa import/export.

📄 src/main.jsx

Ponto de entrada do React
import React from 'react'
import ReactDOM from 'react-dom/client'
import Home from './pages/Home'
import './index.css'

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
   <Home />
  </React.StrictMode>,
)

O que faz cada linha:

• import React from 'react' traz a biblioteca principal do React.
• import ReactDOM from 'react-dom/client' traz a parte do React responsável por conectar com o DOM do navegador (diferente do React Native, por exemplo, que usaria outra biblioteca).
• import Home from './pages/Home' importa o componente principal da aplicação.
• import './index.css' aplica estilos globais (fora dos componentes específicos).
• ReactDOM.createRoot(...) cria a "raiz" da aplicação React, apontando pro elemento <div id="root"> do HTML.
• .render(...) desenha o conteúdo dentro dessa raiz — nesse caso, o componente <Home />.
• <React.StrictMode> é um componente que não renderiza nada visível, mas ativa verificações extras em desenvolvimento (como detectar efeitos colaterais inseguros) — só ajuda a pegar bugs cedo, não afeta produção.

📄 src/pages/Home/index.jsx

Componente principal da tela
import { useEffect , useState , useRef} from 'react'
import './style.css'
import Trash from '../../assets/trash.svg'
import api from '../../services/api'

function Home() {
  const [users, setUsers] = useState([])
  const inputName = useRef()
  const inputAge = useRef()
  const inputEmail = useRef()

  async function getUsers() {
    const usersFromApi = await api.get('/usuarios')
    setUsers(usersFromApi.data)
  }

  async function createUsers(){
    await api.post('/usuarios', {
      name: inputName.current.value,
      age: inputAge.current.value,
      email: inputEmail.current.value
    })
    getUsers()
  }

  async function deleteUsers(id) {
    await api.delete(`/usuarios/${id}`)
    getUsers()
  }

  useEffect(() => {
    getUsers()
  }, [])

  return (
    <div className='container'>
      <form>
        <h1>Cadastro De Usuários</h1>
        <input placeholder="Nome" name="nome" type="text" ref={inputName}/>
        <input placeholder="Idade" name="idade" type="number" ref={inputAge}/>
        <input placeholder="Email" name="email" type="email" ref={inputEmail}/>
        <button type="button" className='cadastrar-button' onClick={createUsers}>Cadastrar</button>
      </form>

      {users.map(user => (
        <div key={user.id} className='card'>
          <div>
            <p>Nome: <span>{user.name}</span></p>
            <p>Idade: <span>{user.age}</span></p>
            <p>Email: <span>{user.email}</span></p>
            <button onClick={() => deleteUsers(user.id)}>
              <img src={Trash} />
            </button>
          </div>
        </div>
      ))}
    </div>
  );
}

export default Home

Imports (linhas 1-4): trazem os três hooks do React, o CSS específico dessa página, o ícone de lixeira (SVG) usado no botão de deletar, e a instância do axios configurada em services/api.js.

Estados e refs (linhas 8-11): users começa como array vazio e vai guardar a lista vinda da API. As três useRef apontam para os inputs do formulário, permitindo ler o valor digitado sem precisar de um useState pra cada campo.

getUsers(): faz um GET em /usuarios via axios. O axios sempre devolve a resposta dentro de um objeto — por isso o dado real está em usersFromApi.data, que é passado pro setUsers para atualizar o estado (e, consequentemente, a tela).

createUsers(): faz um POST em /usuarios, enviando um objeto com os valores lidos direto do DOM via .current.value de cada ref. Depois do cadastro, chama getUsers() de novo pra recarregar a lista com o novo usuário incluído — uma forma simples de manter a tela sincronizada sem gerenciar o array manualmente.

deleteUsers(id): recebe o id do usuário a ser removido, faz um DELETE em /usuarios/{id} (usando template literal pra montar a URL dinamicamente) e recarrega a lista.

useEffect: roda getUsers() assim que o componente aparece na tela pela primeira vez (array de dependências vazio [] = "só na montagem").

JSX (return): o formulário tem três inputs controlados por ref e um botão que, ao ser clicado, chama createUsers. Abaixo do formulário, users.map(...) percorre o array de usuários e gera um <div className="card"> pra cada um, exibindo nome, idade e email, além de um botão com ícone de lixeira que chama deleteUsers(user.id). O key={user.id} é obrigatório em listas no React — ajuda ele a identificar qual item mudou, foi adicionado ou removido, sem precisar redesenhar a lista inteira.

📄 src/pages/Home/style.css

📄 src/services/api.js

Configuração do axios
import axios from 'axios'

const api = axios.create({
  baseURL: 'http://localhost:3000'
})

export default api

axios.create({ baseURL }) cria uma "cópia customizada" do axios já configurada com a URL base do servidor. Assim, no componente, em vez de escrever axios.get('http://localhost:3000/usuarios') toda vez, basta api.get('/usuarios'). Isso centraliza a URL em um único lugar — se o backend mudar de endereço (ex: for pra produção), só precisa trocar aqui.

📄 server.js (back-end)

Servidor Express + Prisma

Código completo já está na seção 5. Explicação linha a linha do essencial:

• import express from "express" e const app = express() criam a aplicação do servidor.
• import pkg from '@prisma/client'; const { PrismaClient } = pkg — importa o client do Prisma de um jeito compatível com ES Modules (o pacote é exportado como CommonJS, por isso o import "estranho" desestruturando depois).
• const prisma = new PrismaClient() cria a instância que conversa com o banco de dados.
• app.use(express.json()) permite ler req.body em JSON.
• app.use(cors()) libera requisições vindas de outra porta (o front-end).
• Cada app.METODO('/rota', async (req, res) => {...}) define um endpoint: req traz os dados da requisição (req.body, req.params, req.query), res é usado pra devolver a resposta (res.status(codigo).json(dados)).
• req.params.id pega o :id da URL (ex: /usuarios/5 → id = "5").
• req.query pega parâmetros depois do ? na URL (ex: /usuarios?name=Luiz).
• app.listen(3000) coloca o servidor escutando na porta 3000.

Todo o código já vinha com pequenos ajustes necessários (parênteses faltando no findMany, resposta correta no PUT) — essas correções estão detalhadas na seção 8.
